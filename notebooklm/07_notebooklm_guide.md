## חלק ב' — אילו פיצ'רים של NotebookLM להפעיל ובאיזה סדר

### 1. Audio Overview (Deep Dive) — לתחילת הלמידה
**מה זה:** שני מגישים וירטואליים מנהלים פודקאסט על החומר שלך.

**למה זה שימושי כאן:** אתה בדרך לראיון, כלומר אתה צריך לדעת **לדבר** על הפרויקט, לא רק לדעת אותו. שמיעת החומר בשיחה חושפת אותך לניסוחים בעל פה.

**חשוב:** יש אפשרות **"Customize"** לפני היצירה — נצל אותה. פרומפט להתאמה:

```
Focus on the technical decisions and their trade-offs: why hybrid search over
pure vector search, why RRF instead of score normalization, why pgvector over a
dedicated vector database, and why LLM reranking over a cross-encoder. Assume the
listener is a junior backend developer preparing for a technical interview.
Explain each concept from first principles, then explain how this specific
project implemented it. Spend extra time on the RRF formula and on the ablation
study methodology.
```

יש גם מצב **Interactive Mode** שבו אפשר להתפרץ ולשאול את המגישים — טוב לתרגול.

### 2. Mind Map — למפות את המערכת בראש
**מה זה:** NotebookLM מייצר מפת חשיבה היררכית מהמקורות.

**למה:** בראיון תצטרך לצייר את הארכיטקטורה על לוח. מפת חשיבה עוזרת לקבע את המבנה ההיררכי: מערכת → צינורות → שלבים → החלטות.

### 3. Chat + Saved Notes — הליבה
כאן תעביר את רוב הזמן. השתמש בפרומפטים בחלק ג'. **כל תשובה טובה — שמור כ-Note** (כפתור Save to note). ההערות השמורות הופכות בעצמן למקור שאפשר לשאול עליו.

### 4. Study Guide / Briefing Doc — לחזרה מהירה
בלוח ה-Studio יש כפתורי יצירה מוכנים:
- **Study Guide** — שאלות חזרה + מונחון. מצוין ליום שלפני.
- **Briefing Doc** — תקציר מנהלים. טוב לרענון של 10 דקות לפני הראיון.
- **FAQ** — שאלות נפוצות. חופף לבנק השאלות שלך אבל בניסוח אחר, וזה מועיל.
- **Timeline** — יבנה את מהלך הפרויקט מהקומיטים.

### 5. Video Overview
סרטון קצר עם סליידים. שימושי אם אתה לומד ויזואלית.

### 6. Sources → Discover
מאפשר להוסיף מקורות מהאינטרנט. שימושי להוסיף את התיעוד של pgvector או את המאמר המקורי של RRF, אם תרצה להעמיק.

### 🎯 סדרה 3 — עומק אלגוריתמי (יום 1, ערב)

```
הסבר לי את RRF — Reciprocal Rank Fusion — מאפס. מה הנוסחה, למה משתמשים בדירוג
ולא בציון, למה הקבוע הוא 60, ומה היה קורה עם k=0 או k=1000. תן לי דוגמה מספרית
עם שלושה מסמכים.
```

```
קח שאילתה לדוגמה: "כמה מרוויח DevOps בכיר בתל אביב?" ועקוב אחריה דרך כל
הצינור. מה בדיוק נשלח ל-OpenAI בכל שלב, מה חוזר, ואיך זה משפיע על השלב הבא.
כלול את שאילתת ה-SQL שרצה בפועל.
```

```
מהו Hybrid Search ולמה הוא עדיף על חיפוש וקטורי בלבד? תן לי דוגמה קונקרטית
לשאילתה שחיפוש סמנטי לבד היה נכשל בה, ודוגמה לשאילתה שחיפוש מילות מפתח לבד
היה נכשל בה.
```

```
הסבר את שלושת מדדי ההערכה — Hit Rate, MRR ו-NDCG. לכל אחד: הנוסחה, מה הוא מודד,
ומה הוא מפספס. תן דוגמה מספרית שבה Hit Rate גבוה אבל MRR נמוך, והסבר מה זה אומר
על המערכת.
```

## חלק ד' — טיפים לשימוש נכון

**1. תמיד בקש מקורות.** NotebookLM מציין ציטוטים למקור. אם תשובה מגיעה בלי ציטוט — היא עלולה להיות המצאה. לחץ על הציטוט וודא.

**2. השתמש ב-Source selection.** אפשר לסמן רק חלק מהמקורות לפני שאילתה. למשל: לשאלות קוד — סמן רק את `06_full_source_code.md`; לשאלות תיאוריה — רק את `rag.md` ואת `02`.

**3. שמור כל תשובה טובה כ-Note.** צבירת ההערות היא הסיכום האישי שלך, והוא נבנה תוך כדי למידה ולא אחריה.

**4. אל תלמד בקריאה פסיבית — תרגל בעל פה.** סדרה 5 היא הכי חשובה. הראיון הוא מבחן דיבור, לא מבחן ידע.

**5. עדכן את המסמכים אחרי שתריץ את ה-ablation.** ברגע שיהיו לך המספרים האמיתיים (מסמך 03, סעיף 4) — מלא אותם, העלה מחדש את הקובץ ל-NotebookLM, ובקש: "נתח את תוצאות ה-ablation שלי. איזה רכיב תרם הכי הרבה, ומה זה אומר על המערכת?"
